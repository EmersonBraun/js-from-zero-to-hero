# `this`, Prototypes & Classes

## The `this` Keyword

`this` is one of the most confusing parts of JavaScript — but it follows clear, deterministic rules. The value of `this` is **not determined by where a function is defined, but by how it is called**. This is the opposite of closures (which are determined by where a function is defined).

> "In most cases, the value of `this` is determined by how a function is called (runtime binding). It can't be set by assignment during execution, and it may be different each time the function is called."
>
> — [MDN: this](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/this)

There are **four binding rules** for `this`, applied in order of precedence.

---

## The Four Binding Rules

### Rule 1: Default Binding

When a function is called as a **plain, standalone function** (not as a method), `this` defaults to:

- The **global object** (`window` in browsers, `global` in Node.js) in non-strict mode
- `undefined` in **strict mode**

```js
function showThis() {
  console.log(this);
}

showThis(); // window (browser) or global (Node) — or undefined in strict mode
```

```js
"use strict";
function showThis() {
  console.log(this); // undefined
}
showThis();
```

> Further reading: [MDN: strict mode](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode)

### Rule 2: Implicit Binding

When a function is called as a **method of an object**, `this` refers to the object to the **left of the dot** at call time:

```js
const user = {
  name: "Alice",
  greet() {
    console.log(`Hello, I'm ${this.name}`);
  },
};

user.greet(); // "Hello, I'm Alice" — this = user
```

**The implicit binding can be lost** when methods are extracted and called standalone:

```js
const { greet } = user;
greet(); // "Hello, I'm undefined" — this is now global/undefined, not user!
```

This is a very common bug. The function `greet` no longer has an implicit receiver — it reverts to default binding.

### Rule 3: Explicit Binding — `call`, `apply`, and `bind`

You can forcefully set `this` using three built-in methods:

**`Function.prototype.call(thisArg, arg1, arg2, ...)`** — calls function immediately with a specific `this`:

```js
function introduce(greeting) {
  console.log(`${greeting}, I'm ${this.name}`);
}

const person = { name: "Bob" };
introduce.call(person, "Hey"); // "Hey, I'm Bob"
```

**`Function.prototype.apply(thisArg, [argsArray])`** — same as `call`, but arguments are passed as an array:

```js
introduce.apply(person, ["Howdy"]); // "Howdy, I'm Bob"
```

**`Function.prototype.bind(thisArg, ...partialArgs)`** — returns a **new function** permanently bound to `this`. Unlike `call`/`apply`, it does not call the function immediately:

```js
const bobIntro = introduce.bind(person);
bobIntro("Hi"); // "Hi, I'm Bob"

// bind also supports partial application:
const greetBob = introduce.bind(person, "Hello");
greetBob(); // "Hello, I'm Bob"
```

> Further reading: [MDN: Function.prototype.bind](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/bind)

### Rule 4: `new` Binding

When a function is called with the `new` keyword, four things happen automatically:

1. A brand new empty object `{}` is created
2. The new object's `[[Prototype]]` is set to `Constructor.prototype`
3. The function is called with `this` pointing to the new object
4. The new object is returned (unless the constructor explicitly returns a different object)

```js
function Person(name, age) {
  this.name = name; // this = the new object
  this.age = age;
}

const alice = new Person("Alice", 30);
console.log(alice.name); // "Alice"
console.log(alice instanceof Person); // true
```

> Further reading: [MDN: new operator](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/new)

### Binding Precedence

When multiple rules could apply, `new` > explicit > implicit > default.

## Arrow Functions and Lexical `this`

Arrow functions `() => {}` do **not** have their own `this`. Instead, they **inherit `this` from the enclosing lexical scope** at the time they are defined. This is called **lexical `this`**.

```js
const timer = {
  seconds: 0,
  start() {
    // 'this' here is the timer object
    setInterval(() => {
      this.seconds++; // arrow function: this = timer (lexical)
      console.log(this.seconds);
    }, 1000);
  },
};

timer.start(); // 1, 2, 3, ...
```

If we used a regular function in `setInterval`, `this` would be `window`/`undefined` (default binding), not `timer`.

> Further reading: [MDN: Arrow function expressions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions)

### The `that = this` Pattern (Pre-Arrow)

Before arrow functions, developers used a variable (often named `self` or `that`) to capture `this`:

```js
const timer = {
  seconds: 0,
  start() {
    const self = this; // capture this
    setInterval(function () {
      self.seconds++; // use captured reference
      console.log(self.seconds);
    }, 1000);
  },
};
```

Arrow functions made this pattern obsolete.

## The Prototype Chain

Every JavaScript object has an internal link to another object called its **prototype** (stored as `[[Prototype]]`, accessible via `Object.getPrototypeOf()` or the legacy `__proto__`). When you access a property on an object and it is not found, JavaScript automatically walks up the prototype chain:

```
myObj → Object.prototype → null
```

```js
const animal = {
  type: "Animal",
  describe() {
    return `I am a ${this.type}`;
  },
};

const dog = Object.create(animal); // dog's [[Prototype]] = animal
dog.type = "Dog";

console.log(dog.describe()); // "I am a Dog"
// describe is not on dog itself — it's found on dog's prototype (animal)
```

> Further reading: [MDN: Inheritance and the prototype chain](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Inheritance_and_the_prototype_chain)

### `Object.create`

`Object.create(proto)` creates a new object with `proto` as its `[[Prototype]]`. This is the purest way to set up prototype delegation:

```js
const vehicleProto = {
  describe() {
    return `${this.make} ${this.model} (${this.year})`;
  },
};

const car = Object.create(vehicleProto);
car.make = "Toyota";
car.model = "Camry";
car.year = 2023;

console.log(car.describe()); // "Toyota Camry (2023)"
console.log(Object.getPrototypeOf(car) === vehicleProto); // true
```

> Further reading: [MDN: Object.create](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/create)

### Constructor Functions and `prototype`

Constructor functions predate `class` syntax. Every function has a `prototype` property — an object that becomes the `[[Prototype]]` of instances created with `new`:

```js
function Animal(name) {
  this.name = name;
}

// Methods on the prototype are SHARED by all instances
Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

const cat = new Animal("Cat");
const dog = new Animal("Dog");

console.log(cat.speak()); // "Cat makes a sound."
console.log(dog.speak()); // "Dog makes a sound."

// Both instances share the same speak function:
console.log(cat.speak === dog.speak); // true — memory efficient!
```

Putting methods on the prototype (rather than inside the constructor) is memory-efficient: instead of each instance having its own copy, they all share one via the chain.

## ES6 Classes: Syntactic Sugar

The `class` keyword, introduced in ES6, provides a cleaner syntax for the same prototype-based mechanism. Classes are **not** a new object model — they are syntactic sugar over constructor functions and prototypes.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

const cat = new Animal("Cat");
console.log(cat.speak()); // "Cat makes a sound."

// Under the hood, speak is still on the prototype:
console.log(typeof Animal.prototype.speak); // "function"
```

### Static Methods

Static methods belong to the class itself, not to instances. They are called on the class directly:

```js
class MathUtils {
  static add(a, b) {
    return a + b;
  }

  static PI = 3.14159;
}

console.log(MathUtils.add(2, 3)); // 5
console.log(MathUtils.PI);        // 3.14159

const m = new MathUtils();
// m.add(2, 3); // TypeError: m.add is not a function
```

> Further reading: [MDN: static](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/static)

### Public and Private Fields (`#`)

ES2022 introduced **class fields**. Private fields use the `#` prefix and are truly inaccessible from outside the class — enforced at the language level, not just by convention:

```js
class BankAccount {
  #balance; // private field declaration
  owner;    // public field

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const account = new BankAccount("Alice", 1000);
account.deposit(500);
console.log(account.balance); // 1500
// console.log(account.#balance); // SyntaxError: Private field '#balance'
```

> Further reading: [MDN: Private class features](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_class_fields)

### Inheritance with `extends` and `super`

`extends` sets up the prototype chain between classes. `super` calls the parent class's constructor or methods:

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // MUST call super() before using this
    this.breed = breed;
  }

  speak() {
    return `${this.name} barks!`;
  }

  describe() {
    return `${super.speak()} I am a ${this.breed}.`;
  }
}

const rex = new Dog("Rex", "Labrador");
console.log(rex.speak());    // "Rex barks!"
console.log(rex.describe()); // "Rex makes a sound. I am a Labrador."
console.log(rex instanceof Animal); // true — prototype chain
console.log(rex instanceof Dog);    // true
```

> Further reading: [MDN: extends](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/extends)

### Architecture Overview

```js
class Player {
  #name;
  #symbol;
  #score;

  constructor(name, symbol) {
    this.#name = name;
    this.#symbol = symbol;
    this.#score = 0;
  }

  get name() { return this.#name; }
  get symbol() { return this.#symbol; }
  get score() { return this.#score; }

  addWin() { this.#score++; }
}

class Board {
  #cells;

  constructor() {
    this.#cells = Array(9).fill(null);
  }

  mark(index, symbol) {
    if (this.#cells[index] !== null) throw new Error("Cell taken");
    this.#cells[index] = symbol;
  }

  checkWinner() {
    const lines = [[0,1,2],[3,4,5],[6,7,8],[0,3,6],[1,4,7],[2,5,8],[0,4,8],[2,4,6]];
    return lines.some(([a,b,c]) =>
      this.#cells[a] && this.#cells[a] === this.#cells[b] && this.#cells[a] === this.#cells[c]
    );
  }
}
```

Note how `this` inside class methods always refers to the instance, because event handlers should always use arrow functions or `bind` to preserve the game instance reference.

### Challenge 1

Refactor the game to support an **AI opponent** by extending `Player` with a `ComputerPlayer` subclass. The subclass should override a `chooseMove(board)` method that picks a random available cell.

### Challenge 2

Add a **score tracking** system using private class fields. Each player's win count should be stored as a private field and only accessible through a getter. Persist the score to `localStorage` across page refreshes.

## Summary

- `this` is determined **at call time** by four rules: default, implicit, explicit (`call`/`apply`/`bind`), and `new`.
- Arrow functions have **no own `this`** — they inherit it lexically from their enclosing scope.
- The `that = this` pattern was the pre-arrow workaround.
- Every object has a `[[Prototype]]` — a link to another object. Property lookups walk this **prototype chain**.
- `Object.create(proto)` creates an object with a specific prototype.
- Constructor functions + `prototype` property is the classic approach to shared methods.
- `class` is syntactic sugar: cleaner syntax, same prototype-based mechanics.
- `static` members belong to the class, not instances.
- Private fields `#field` are enforced by the language — not just a naming convention.
- `extends` + `super` enable clean, readable inheritance.
