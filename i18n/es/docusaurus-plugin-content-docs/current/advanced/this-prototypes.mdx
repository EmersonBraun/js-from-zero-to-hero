# `this`, Prototipos y Clases

## La Palabra Clave `this`

`this` es una de las partes más confusas de JavaScript — pero sigue reglas claras y deterministas. El valor de `this` **no está determinado por dónde se define una función, sino por cómo se llama**. Esto es lo opuesto de los closures (que están determinados por dónde se define una función).

> "En la mayoría de los casos, el valor de `this` está determinado por cómo se llama a una función (binding en tiempo de ejecución). No puede establecerse por asignación durante la ejecución, y puede ser diferente cada vez que se llama a la función."
>
> — [MDN: this](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/this)

Hay **cuatro reglas de binding** para `this`, aplicadas en orden de precedencia.

---

## Las Cuatro Reglas de Binding

### Regla 1: Binding por Defecto

Cuando una función se llama como una **función independiente y sin contexto** (no como método), `this` toma por defecto:

- El **objeto global** (`window` en navegadores, `global` en Node.js) en modo no estricto
- `undefined` en **modo estricto**

```js
function showThis() {
  console.log(this);
}

showThis(); // window (navegador) o global (Node) — o undefined en modo estricto
```

```js
"use strict";
function showThis() {
  console.log(this); // undefined
}
showThis();
```

> Lectura adicional: [MDN: strict mode](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode)

### Regla 2: Binding Implícito

Cuando una función se llama como un **método de un objeto**, `this` se refiere al objeto a la **izquierda del punto** en el momento de la llamada:

```js
const user = {
  name: "Alice",
  greet() {
    console.log(`Hello, I'm ${this.name}`);
  },
};

user.greet(); // "Hello, I'm Alice" — this = user
```

**El binding implícito puede perderse** cuando los métodos se extraen y se llaman de forma independiente:

```js
const { greet } = user;
greet(); // "Hello, I'm undefined" — ¡this ahora es global/undefined, no user!
```

Este es un bug muy común. La función `greet` ya no tiene un receptor implícito — revierte al binding por defecto.

### Regla 3: Binding Explícito — `call`, `apply` y `bind`

Puedes establecer `this` forzadamente usando tres métodos integrados:

**`Function.prototype.call(thisArg, arg1, arg2, ...)`** — llama a la función inmediatamente con un `this` específico:

```js
function introduce(greeting) {
  console.log(`${greeting}, I'm ${this.name}`);
}

const person = { name: "Bob" };
introduce.call(person, "Hey"); // "Hey, I'm Bob"
```

**`Function.prototype.apply(thisArg, [argsArray])`** — igual que `call`, pero los argumentos se pasan como un array:

```js
introduce.apply(person, ["Howdy"]); // "Howdy, I'm Bob"
```

**`Function.prototype.bind(thisArg, ...partialArgs)`** — retorna una **nueva función** permanentemente vinculada a `this`. A diferencia de `call`/`apply`, no llama a la función inmediatamente:

```js
const bobIntro = introduce.bind(person);
bobIntro("Hi"); // "Hi, I'm Bob"

// bind también soporta aplicación parcial:
const greetBob = introduce.bind(person, "Hello");
greetBob(); // "Hello, I'm Bob"
```

> Lectura adicional: [MDN: Function.prototype.bind](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/bind)

### Regla 4: Binding con `new`

Cuando una función se llama con la palabra clave `new`, cuatro cosas suceden automáticamente:

1. Se crea un nuevo objeto vacío `{}`
2. El `[[Prototype]]` del nuevo objeto se establece en `Constructor.prototype`
3. La función se llama con `this` apuntando al nuevo objeto
4. El nuevo objeto se retorna (a menos que el constructor retorne explícitamente un objeto diferente)

```js
function Person(name, age) {
  this.name = name; // this = el nuevo objeto
  this.age = age;
}

const alice = new Person("Alice", 30);
console.log(alice.name); // "Alice"
console.log(alice instanceof Person); // true
```

> Lectura adicional: [MDN: new operator](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/new)

### Precedencia de Binding

Cuando podrían aplicarse múltiples reglas, la prioridad es: `new` > explícito > implícito > por defecto.

## Funciones Flecha y `this` Léxico

Las funciones flecha `() => {}` **no** tienen su propio `this`. En cambio, **heredan `this` del alcance léxico que las envuelve** en el momento en que se definen. Esto se llama **`this` léxico**.

```js
const timer = {
  seconds: 0,
  start() {
    // 'this' aquí es el objeto timer
    setInterval(() => {
      this.seconds++; // función flecha: this = timer (léxico)
      console.log(this.seconds);
    }, 1000);
  },
};

timer.start(); // 1, 2, 3, ...
```

Si usáramos una función regular en `setInterval`, `this` sería `window`/`undefined` (binding por defecto), no `timer`.

> Lectura adicional: [MDN: Arrow function expressions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions)

### El Patrón `that = this` (Pre-Flecha)

Antes de las funciones flecha, los desarrolladores usaban una variable (a menudo llamada `self` o `that`) para capturar `this`:

```js
const timer = {
  seconds: 0,
  start() {
    const self = this; // capturar this
    setInterval(function () {
      self.seconds++; // usar referencia capturada
      console.log(self.seconds);
    }, 1000);
  },
};
```

Las funciones flecha hicieron obsoleto este patrón.

## La Cadena de Prototipos

Cada objeto JavaScript tiene un enlace interno a otro objeto llamado su **prototipo** (almacenado como `[[Prototype]]`, accesible a través de `Object.getPrototypeOf()` o el `__proto__` heredado). Cuando accedes a una propiedad en un objeto y no se encuentra, JavaScript recorre automáticamente la cadena de prototipos:

```
myObj → Object.prototype → null
```

```js
const animal = {
  type: "Animal",
  describe() {
    return `I am a ${this.type}`;
  },
};

const dog = Object.create(animal); // el [[Prototype]] de dog = animal
dog.type = "Dog";

console.log(dog.describe()); // "I am a Dog"
// describe no está en dog mismo — se encuentra en el prototipo de dog (animal)
```

> Lectura adicional: [MDN: Inheritance and the prototype chain](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Inheritance_and_the_prototype_chain)

### `Object.create`

`Object.create(proto)` crea un nuevo objeto con `proto` como su `[[Prototype]]`. Esta es la forma más pura de configurar delegación de prototipos:

```js
const vehicleProto = {
  describe() {
    return `${this.make} ${this.model} (${this.year})`;
  },
};

const car = Object.create(vehicleProto);
car.make = "Toyota";
car.model = "Camry";
car.year = 2023;

console.log(car.describe()); // "Toyota Camry (2023)"
console.log(Object.getPrototypeOf(car) === vehicleProto); // true
```

> Lectura adicional: [MDN: Object.create](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/create)

### Funciones Constructoras y `prototype`

Las funciones constructoras son anteriores a la sintaxis `class`. Cada función tiene una propiedad `prototype` — un objeto que se convierte en el `[[Prototype]]` de las instancias creadas con `new`:

```js
function Animal(name) {
  this.name = name;
}

// Los métodos en el prototipo son COMPARTIDOS por todas las instancias
Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

const cat = new Animal("Cat");
const dog = new Animal("Dog");

console.log(cat.speak()); // "Cat makes a sound."
console.log(dog.speak()); // "Dog makes a sound."

// Ambas instancias comparten la misma función speak:
console.log(cat.speak === dog.speak); // true — ¡eficiente en memoria!
```

Poner métodos en el prototipo (en lugar de dentro del constructor) es eficiente en memoria: en vez de que cada instancia tenga su propia copia, todas comparten una a través de la cadena.

## Clases ES6: Azúcar Sintáctico

La palabra clave `class`, introducida en ES6, proporciona una sintaxis más limpia para el mismo mecanismo basado en prototipos. Las clases **no** son un nuevo modelo de objetos — son azúcar sintáctico sobre funciones constructoras y prototipos.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

const cat = new Animal("Cat");
console.log(cat.speak()); // "Cat makes a sound."

// Internamente, speak todavía está en el prototipo:
console.log(typeof Animal.prototype.speak); // "function"
```

### Métodos Estáticos

Los métodos estáticos pertenecen a la clase en sí, no a las instancias. Se llaman directamente en la clase:

```js
class MathUtils {
  static add(a, b) {
    return a + b;
  }

  static PI = 3.14159;
}

console.log(MathUtils.add(2, 3)); // 5
console.log(MathUtils.PI);        // 3.14159

const m = new MathUtils();
// m.add(2, 3); // TypeError: m.add is not a function
```

> Lectura adicional: [MDN: static](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/static)

### Campos Públicos y Privados (`#`)

ES2022 introdujo los **campos de clase**. Los campos privados usan el prefijo `#` y son verdaderamente inaccesibles desde fuera de la clase — aplicado a nivel del lenguaje, no solo por convención:

```js
class BankAccount {
  #balance; // declaración de campo privado
  owner;    // campo público

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const account = new BankAccount("Alice", 1000);
account.deposit(500);
console.log(account.balance); // 1500
// console.log(account.#balance); // SyntaxError: Private field '#balance'
```

> Lectura adicional: [MDN: Private class features](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_class_fields)

### Herencia con `extends` y `super`

`extends` configura la cadena de prototipos entre clases. `super` llama al constructor o métodos de la clase padre:

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // DEBE llamar super() antes de usar this
    this.breed = breed;
  }

  speak() {
    return `${this.name} barks!`;
  }

  describe() {
    return `${super.speak()} I am a ${this.breed}.`;
  }
}

const rex = new Dog("Rex", "Labrador");
console.log(rex.speak());    // "Rex barks!"
console.log(rex.describe()); // "Rex makes a sound. I am a Labrador."
console.log(rex instanceof Animal); // true — cadena de prototipos
console.log(rex instanceof Dog);    // true
```

> Lectura adicional: [MDN: extends](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/extends)

### Visión General de la Arquitectura

```js
class Player {
  #name;
  #symbol;
  #score;

  constructor(name, symbol) {
    this.#name = name;
    this.#symbol = symbol;
    this.#score = 0;
  }

  get name() { return this.#name; }
  get symbol() { return this.#symbol; }
  get score() { return this.#score; }

  addWin() { this.#score++; }
}

class Board {
  #cells;

  constructor() {
    this.#cells = Array(9).fill(null);
  }

  mark(index, symbol) {
    if (this.#cells[index] !== null) throw new Error("Cell taken");
    this.#cells[index] = symbol;
  }

  checkWinner() {
    const lines = [[0,1,2],[3,4,5],[6,7,8],[0,3,6],[1,4,7],[2,5,8],[0,4,8],[2,4,6]];
    return lines.some(([a,b,c]) =>
      this.#cells[a] && this.#cells[a] === this.#cells[b] && this.#cells[a] === this.#cells[c]
    );
  }
}
```

Nota cómo `this` dentro de los métodos de clase siempre se refiere a la instancia, porque los handlers de eventos siempre deben usar funciones flecha o `bind` para preservar la referencia a la instancia del juego.

## Resumen

- `this` se determina **en el momento de la llamada** por cuatro reglas: por defecto, implícito, explícito (`call`/`apply`/`bind`) y `new`.
- Las funciones flecha **no tienen su propio `this`** — lo heredan léxicamente de su alcance envolvente.
- El patrón `that = this` era la solución pre-flecha.
- Cada objeto tiene un `[[Prototype]]` — un enlace a otro objeto. Las búsquedas de propiedades recorren esta **cadena de prototipos**.
- `Object.create(proto)` crea un objeto con un prototipo específico.
- Las funciones constructoras + propiedad `prototype` es el enfoque clásico para métodos compartidos.
- `class` es azúcar sintáctico: sintaxis más limpia, misma mecánica basada en prototipos.
- Los miembros `static` pertenecen a la clase, no a las instancias.
- Los campos privados `#field` son aplicados por el lenguaje — no solo una convención de nombres.
- `extends` + `super` habilitan herencia limpia y legible.
