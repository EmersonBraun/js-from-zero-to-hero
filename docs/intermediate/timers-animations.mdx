# Timers & Animations

JavaScript can schedule code to run in the future, repeat on an interval, and synchronize with the browser's rendering cycle. These capabilities are the foundation of countdowns, games, and smooth animations.

## Theory

### setTimeout

`setTimeout` schedules a function to run **once** after a delay (in milliseconds).

```js
const id = setTimeout(() => {
  console.log("This runs after 2 seconds");
}, 2000);

// Cancel before it fires:
clearTimeout(id);
```

The callback is placed in the **task queue** after the delay and runs when the call stack is empty — so delays are minimum, not guaranteed, times.

MDN Reference: [setTimeout](https://developer.mozilla.org/en-US/docs/Web/API/setTimeout)

### setInterval

`setInterval` calls a function **repeatedly** at a fixed interval.

```js
let count = 0;
const id = setInterval(() => {
  count++;
  console.log(`Tick ${count}`);
  if (count === 5) clearInterval(id);
}, 1000);
```

Always store the ID so you can stop the interval with `clearInterval` when done — forgetting to clear is a common memory-leak source.

MDN Reference: [setInterval](https://developer.mozilla.org/en-US/docs/Web/API/setInterval)

### clearTimeout and clearInterval

Both `clearTimeout` and `clearInterval` accept the numeric ID returned by their respective scheduling functions.

```js
const timerId = setTimeout(fn, 5000);
clearTimeout(timerId); // fn never runs

const intervalId = setInterval(fn, 500);
clearInterval(intervalId); // stops the repeating calls
```

### requestAnimationFrame

`requestAnimationFrame` (rAF) schedules a callback to run **before the next repaint**, roughly 60 times per second (every ~16.7 ms). It is the preferred tool for animations because:

- It pauses when the tab is hidden (saves CPU/battery).
- It syncs with the display refresh rate.
- It avoids the visual stutter that `setInterval` can cause.

```js
function animate(timestamp) {
  // timestamp is a DOMHighResTimeStamp
  draw(timestamp);
  requestAnimationFrame(animate); // schedule the next frame
}
requestAnimationFrame(animate); // kick off the loop
```

To stop a rAF loop, call `cancelAnimationFrame(id)` with the returned ID.

MDN Reference: [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/window/requestAnimationFrame)

### CSS Animations Triggered by JavaScript

You can start CSS animations by toggling classes with JavaScript:

```css
/* style.css */
.ball {
  transition: transform 0.5s ease;
}
.ball.jump {
  transform: translateY(-150px);
}
```

```js
const ball = document.querySelector(".ball");
ball.classList.add("jump");

setTimeout(() => ball.classList.remove("jump"), 500);
```

For more complex sequences, the **Web Animations API** lets you control animations entirely from JS:

```js
element.animate(
  [{ transform: "translateY(0)" }, { transform: "translateY(-150px)" }],
  { duration: 400, easing: "ease-out", fill: "forwards" }
);
```

MDN Reference: [Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API)

### Game Loops

A game loop updates state and redraws the screen as fast as possible. Using `requestAnimationFrame` gives a smooth, battery-friendly loop:

```js
let lastTime = 0;

function gameLoop(timestamp) {
  const delta = timestamp - lastTime; // time since last frame (ms)
  lastTime = timestamp;

  update(delta); // move objects, check collisions
  render();      // draw everything

  requestAnimationFrame(gameLoop);
}

requestAnimationFrame(gameLoop);
```

Using `delta` (elapsed time) instead of a fixed step makes the game **frame-rate independent** — it runs at the same speed on a 60 Hz and a 120 Hz display.

  // Accumulate the total elapsed time (delta between frames) and
  // return a Promise that resolves with { frameCount, totalTime }

### Walkthrough

The timer state is a plain object updated by `setInterval`:

```js
let intervalId = null;
let remaining = 0; // seconds

function start() {
  if (intervalId) return; // already running
  intervalId = setInterval(() => {
    if (remaining <= 0) {
      clearInterval(intervalId);
      intervalId = null;
      onFinish();
      return;
    }
    remaining--;
    render();
  }, 1000);
}

function pause() {
  clearInterval(intervalId);
  intervalId = null;
}

function reset(seconds) {
  pause();
  remaining = seconds;
  render();
}

function render() {
  const m = String(Math.floor(remaining / 60)).padStart(2, "0");
  const s = String(remaining % 60).padStart(2, "0");
  display.textContent = `${m}:${s}`;
}
```

Key points:

- Store the interval ID so it can be cleared.
- Track `remaining` separately from the display.
- `padStart(2, "0")` ensures two-digit formatting.

## Project 2: Mario Jump

A side-scrolling platformer in which Mario must jump over obstacles. Built with `requestAnimationFrame` and CSS class toggling.

### Walkthrough

```js
const mario = document.querySelector(".mario");
const obstacle = document.querySelector(".obstacle");

let gameOver = false;
let animationId;

function jump() {
  if (mario.classList.contains("jump")) return;
  mario.classList.add("jump");
  setTimeout(() => mario.classList.remove("jump"), 500);
}

function checkCollision() {
  const marioRect = mario.getBoundingClientRect();
  const obstacleRect = obstacle.getBoundingClientRect();
  return (
    marioRect.right > obstacleRect.left &&
    marioRect.left < obstacleRect.right &&
    marioRect.bottom > obstacleRect.top &&
    marioRect.top < obstacleRect.bottom
  );
}

function gameLoop() {
  if (checkCollision()) {
    gameOver = true;
    obstacle.style.animation = "none";
    return;
  }
  animationId = requestAnimationFrame(gameLoop);
}

document.addEventListener("keydown", (e) => {
  if (e.code === "Space" && !gameOver) jump();
});

requestAnimationFrame(gameLoop);
```

The obstacle's horizontal movement is handled by a CSS keyframe animation, keeping the JS loop focused purely on collision detection.

## Summary

- `setTimeout` runs code **once** after a delay; always store and clear the ID when done.
- `setInterval` repeats code on a fixed schedule; **always** clear it to prevent memory leaks.
- `requestAnimationFrame` is the right tool for animations and game loops — it syncs with the screen, is paused when the tab is hidden, and avoids stutter.
- CSS class toggling is a clean way to trigger CSS transitions and keyframe animations from JavaScript.
- **Delta time** makes game loops frame-rate independent: multiply speeds by the elapsed time instead of a fixed step.
- The **debounce** pattern (built on `setTimeout`) prevents a fast-firing function from running until the user pauses.
