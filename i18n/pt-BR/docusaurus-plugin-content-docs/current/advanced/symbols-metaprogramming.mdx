# Symbols & Metaprogramação

Metaprogramação é a prática de escrever código que opera sobre outro código — inspecionando-o, modificando seu comportamento, ou interceptando suas operações em tempo de execução. JavaScript fornece três pilares para isso: **Symbols** (chaves únicas que evitam colisões), **Proxy** (intercepta operações fundamentais em objetos), e **Reflect** (uma API limpa para essas mesmas operações).

---

## 1. O Que São Symbols e Por Que Existem

Antes dos Symbols, todas as chaves de objeto eram strings. Isso criava problemas quando múltiplas bibliotecas tentavam adicionar propriedades ao mesmo objeto — os nomes podiam colidir silenciosamente.

`Symbol()` cria um **valor primitivo garantidamente único**. Dois symbols nunca são iguais, mesmo que criados com a mesma descrição.

```js
const a = Symbol('id');
const b = Symbol('id');
console.log(a === b); // false — sempre único
console.log(typeof a); // "symbol"
console.log(a.toString()); // "Symbol(id)"
console.log(a.description); // "id"
```

Symbols não são enumeráveis em loops `for...in`, não aparecem em `Object.keys()`, e são excluídos de `JSON.stringify()`. Isso os torna ideais para anexar metadados ou pontos de extensão sem poluir APIs públicas.

Referência MDN: [Symbol](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol)

---

## 2. Criando Symbols: `Symbol()` vs `Symbol.for()`

`Symbol()` sempre cria um symbol novo e único.

`Symbol.for(key)` usa um **registro global de symbols** — retorna o mesmo symbol para a mesma string de chave, entre realms (iframes, workers).

```js
const s1 = Symbol.for('app.user');
const s2 = Symbol.for('app.user');
console.log(s1 === s2); // true

// Lookup reverso
console.log(Symbol.keyFor(s1)); // "app.user"

// Symbols locais não têm chave de registro
const local = Symbol('local');
console.log(Symbol.keyFor(local)); // undefined
```

Use `Symbol.for()` quando precisar de symbols compartilhados entre realms ou módulos. Use `Symbol()` para pontos de extensão privados/internos.

## 3. Symbols como Chaves de Objeto

```js
const ID = Symbol('id');
const ROLE = Symbol('role');

const user = {
  name: 'Alice',
  [ID]: 42,
  [ROLE]: 'admin',
};

console.log(user[ID]); // 42
console.log(Object.keys(user)); // ["name"] — symbols excluídos
console.log(Object.getOwnPropertySymbols(user)); // [Symbol(id), Symbol(role)]

// JSON.stringify ignora symbols
console.log(JSON.stringify(user)); // {"name":"Alice"}
```

Esse padrão é usado por bibliotecas para anexar estado interno não-enumerável a objetos do usuário sem risco de colisão de chaves.

## 4. Symbols Bem-Conhecidos

JavaScript usa symbols embutidos (armazenados em `Symbol.*`) para se conectar ao comportamento central da linguagem. Esses são chamados **well-known symbols**.

### `Symbol.iterator`

Define o iterador padrão de um objeto. Usado por `for...of`, spread e desestruturação.

```js
class Counter {
  constructor(max) { this.max = max; }

  [Symbol.iterator]() {
    let n = 0, max = this.max;
    return {
      next() {
        return n < max
          ? { value: n++, done: false }
          : { value: undefined, done: true };
      }
    };
  }
}

console.log([...new Counter(4)]); // [0, 1, 2, 3]
```

### `Symbol.toPrimitive`

Controla como um objeto é convertido para um primitivo (número, string ou default).

```js
class Temperature {
  constructor(celsius) { this.celsius = celsius; }

  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.celsius;
    if (hint === 'string') return `${this.celsius}°C`;
    return this.celsius; // default
  }
}

const temp = new Temperature(22);
console.log(+temp);           // 22  (hint numérico)
console.log(`Temp: ${temp}`); // "Temp: 22°C"  (hint de string)
console.log(temp + 0);        // 22  (hint default)
```

Referência MDN: [Symbol.toPrimitive](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol/toPrimitive)

### `Symbol.hasInstance`

Controla o comportamento do `instanceof`.

```js
class EvenNumber {
  static [Symbol.hasInstance](value) {
    return typeof value === 'number' && value % 2 === 0;
  }
}

console.log(4 instanceof EvenNumber); // true
console.log(3 instanceof EvenNumber); // false
```

### `Symbol.toStringTag`

Personaliza a saída de `Object.prototype.toString()`.

```js
class Database {
  get [Symbol.toStringTag]() { return 'Database'; }
}

const db = new Database();
console.log(Object.prototype.toString.call(db)); // "[object Database]"
```

### `Symbol.species`

Especifica o construtor usado quando objetos derivados são criados por métodos como `map`, `filter`, `slice`. Raramente necessário fora de código de framework/biblioteca.

Referência MDN: [Well-known symbols](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol#well-known_symbols)

## 5. O Objeto Proxy

`Proxy` envolve um objeto-alvo e intercepta operações fundamentais por meio de **traps de handler**. Cada operação que você pode realizar em um objeto tem uma trap correspondente.

```js
const proxy = new Proxy(target, handler);
```

O handler é um objeto cujos métodos (traps) interceptam operações no alvo.

Referência MDN: [Proxy](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy)

### Trap `get`

```js
const handler = {
  get(target, prop, receiver) {
    console.log(`Getting: ${String(prop)}`);
    return Reflect.get(target, prop, receiver);
  }
};

const obj = new Proxy({ x: 1 }, handler);
obj.x; // registra "Getting: x", retorna 1
```

### Trap `set`

```js
const validator = {
  set(target, prop, value, receiver) {
    if (prop === 'age' && (typeof value !== 'number' || value < 0)) {
      throw new TypeError('Age must be a non-negative number');
    }
    return Reflect.set(target, prop, value, receiver);
  }
};

const person = new Proxy({}, validator);
person.age = 25;  // OK
person.age = -1;  // TypeError
```

### Trap `has`

Intercepta o operador `in`.

```js
const rangeProxy = new Proxy({}, {
  has(target, prop) {
    const num = Number(prop);
    return num >= 1 && num <= 100;
  }
});

console.log(50 in rangeProxy);  // true
console.log(101 in rangeProxy); // false
```

### Trap `deleteProperty`

```js
const frozen = new Proxy({ a: 1, b: 2 }, {
  deleteProperty(target, prop) {
    console.warn(`Deletion of "${prop}" was blocked`);
    return false; // impede a exclusão
  }
});
```

### Trap `apply`

Intercepta chamadas de função.

```js
function greet(name) { return `Hello, ${name}!`; }

const tracedGreet = new Proxy(greet, {
  apply(target, thisArg, args) {
    console.log(`Called with args: ${JSON.stringify(args)}`);
    return Reflect.apply(target, thisArg, args);
  }
});

tracedGreet('Alice'); // registra args, retorna "Hello, Alice!"
```

## 6. A API Reflect

`Reflect` fornece métodos estáticos espelhando cada trap de Proxy. Ela serve a dois propósitos:

1. **Encaminhar operações das traps de Proxy** — sempre use `Reflect` em vez de operar diretamente no alvo para preservar o comportamento correto de `this` com herança.
2. **Alternativas funcionais aos operadores** — `Reflect.has(obj, key)` vs `key in obj`.

```js
// Em vez de:
target[prop] = value;
// Use nas traps:
Reflect.set(target, prop, value, receiver);

// Em vez de:
delete target[prop];
Reflect.deleteProperty(target, prop);

// Em vez de:
new Ctor(...args);
Reflect.construct(Ctor, args);
```

Referência MDN: [Reflect](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Reflect)

## 7. Padrões Práticos de Metaprogramação

### Proxy de Validação

```js
function createValidated(schema) {
  return new Proxy({}, {
    set(target, prop, value) {
      if (schema[prop] && !schema[prop](value)) {
        throw new TypeError(`Validation failed for "${prop}"`);
      }
      return Reflect.set(target, prop, value);
    }
  });
}

const user = createValidated({
  name: v => typeof v === 'string' && v.length > 0,
  age: v => Number.isInteger(v) && v >= 0 && v <= 150,
});
```

### Proxy de Logging / Rastreamento

```js
function createLogged(target, label = 'Object') {
  return new Proxy(target, {
    get(t, prop, receiver) {
      const value = Reflect.get(t, prop, receiver);
      if (typeof value === 'function') {
        return function(...args) {
          console.log(`[${label}] ${String(prop)}(${args.map(JSON.stringify).join(', ')})`);
          return value.apply(this, args);
        };
      }
      return value;
    }
  });
}
```

### Dados Reativos (estilo Vue)

```js
function reactive(data, onChange) {
  return new Proxy(data, {
    set(target, prop, value, receiver) {
      const old = target[prop];
      const result = Reflect.set(target, prop, value, receiver);
      if (old !== value) onChange(prop, old, value);
      return result;
    }
  });
}

const state = reactive({ count: 0 }, (key, from, to) => {
  console.log(`${key}: ${from} → ${to}`);
});

state.count = 1; // registra "count: 0 → 1"
```

## Resumo

- **Symbols** são primitivas únicas e não-enumeráveis usadas como chaves de objeto livres de colisão ou para anexar metadados não-públicos.
- `Symbol()` cria um symbol local sempre único; `Symbol.for(key)` registra e recupera symbols de um registro global.
- **Well-known symbols** são os ganchos de extensão para comportamentos embutidos da linguagem: `Symbol.iterator` (iteração), `Symbol.toPrimitive` (coerção), `Symbol.hasInstance` (`instanceof`), `Symbol.toStringTag` (tag de tipo), `Symbol.species` (construtor derivado).
- **Proxy** envolve qualquer objeto e intercepta operações por meio de traps (`get`, `set`, `has`, `deleteProperty`, `apply`, e mais).
- Sempre encaminhe para **Reflect** dentro das traps de proxy para preservar o comportamento correto da cadeia de protótipos.
- **Reflect** fornece uma API funcional espelhando cada trap de proxy e cada operador de objeto.
- Padrões práticos de metaprogramação incluem **proxies de validação** (forçar invariantes na atribuição), **proxies de logging** (rastrear todas as operações), e **dados reativos** (disparar efeitos colaterais em mutações, como visto em Vue e MobX).
- Essas primitivas são a fundação dos frameworks JavaScript modernos — entendê-las revela a maquinaria por trás de propriedades computadas, two-way binding e estado observável.
