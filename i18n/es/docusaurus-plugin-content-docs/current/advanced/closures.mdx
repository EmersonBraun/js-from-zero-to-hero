# Closures

## ¿Qué Son los Closures?

Un **closure** es uno de los conceptos más fundamentales — y más incomprendidos — en JavaScript. En esencia, un closure es la combinación de una función y su **entorno léxico**: el conjunto de variables que estaban en el alcance cuando se creó la función, a las cuales retiene acceso incluso después de que el alcance externo haya terminado de ejecutarse.

MDN lo define así:

> "Un closure es la combinación de una función empaquetada (encerrada) con referencias a su estado circundante (el entorno léxico). En otras palabras, un closure te da acceso al alcance de una función externa desde una función interna."
>
> — [MDN: Closures](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Closures)

Para entender los closures, primero necesitas un conocimiento sólido del **alcance léxico** y cómo funciona la **cadena de alcance**.

---

## Alcance Léxico y la Cadena de Alcance

JavaScript usa **alcance léxico** (también llamado **alcance estático**): el alcance de una función está determinado por dónde está **escrita** la función en el código fuente, no desde dónde **se llama**.

```js
const x = 10;

function outer() {
  const y = 20;

  function inner() {
    const z = 30;
    console.log(x, y, z); // 10, 20, 30
  }

  inner();
}

outer();
```

Cuando `inner` se ejecuta, el motor de JavaScript busca la variable `x` recorriendo la **cadena de alcance**:

1. Verificar el propio alcance de `inner` → no encontrado
2. Verificar el alcance de `outer` → no encontrado
3. Verificar el alcance global → encontrado: `x = 10`

Esta cadena se establece **en el momento en que se define la función**, no cuando se llama. Esa es la esencia del alcance léxico.

### El Slot Interno [[scope]]

Cada objeto función en JavaScript tiene una propiedad interna llamada `[[scope]]` (a veces escrita como `[[Environment]]`). Este slot oculto contiene una referencia al **registro de entorno** — el alcance real — en el que se creó la función.

Cuando se invoca una función, se crea un nuevo contexto de ejecución. El puntero de **entorno externo** de ese contexto se establece con lo que estaba almacenado en `[[scope]]`. Esto es lo que forma la cadena de alcance en tiempo de ejecución.

> Lectura adicional: [MDN: Scope](https://developer.mozilla.org/en-US/docs/Glossary/Scope)

## El Modelo Mental de la "Mochila"

Un modelo mental útil para los closures es la **mochila** (o "entorno de variable cerrado", COVE):

> Cuando se crea una función dentro de otra función, la función interna "empaca" una copia de las variables circundantes en una mochila invisible atada a su espalda. Sin importar a dónde viaje la función — incluso después de que la función externa haya retornado y su contexto de ejecución haya sido eliminado de la pila de llamadas — la mochila siempre está ahí.

```js
function makeCounter() {
  let count = 0; // esto se empaca en la mochila del closure

  return function () {
    count++;
    return count;
  };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

`makeCounter` retornó hace mucho, sin embargo `count` todavía está vivo. ¿Por qué? Porque la función retornada tiene una referencia viva a la variable `count` dentro de su closure. El recolector de basura no puede reclamar `count` mientras esa referencia exista.

---

## Cómo JavaScript Gestiona la Memoria de los Closures

Cuando el motor JavaScript crea una función que cierra sobre variables, esas variables se almacenan en el **heap** en lugar de la pila. Los frames de la pila se eliminan cuando una función retorna, pero las asignaciones en el heap persisten mientras algo tenga una referencia a ellas.

El entorno de variables cerrado es esencialmente un objeto en el heap:

```
Heap:
  ClosureEnv { count: 3 }
      ↑
  El [[scope]] de la función counter apunta aquí
```

Esto significa que los closures consumen memoria. Para aplicaciones de larga duración, es importante no retener accidentalmente objetos grandes en closures cuando ya no son necesarios.

> Lectura adicional: [MDN: Memory Management](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Memory_management)

## Patrones Prácticos con Closures

### 1. Funciones Fábrica

Una **función fábrica** es una función que retorna una nueva función personalizada. Los closures hacen esto poderoso:

```js
function multiplier(factor) {
  return (number) => number * factor; // factor está cerrado
}

const double = multiplier(2);
const triple = multiplier(3);

console.log(double(5));  // 10
console.log(triple(5));  // 15
```

Cada llamada a `multiplier` crea un nuevo closure con su propio `factor`. `double` y `triple` son completamente independientes.

### 2. Variables Privadas (Patrón Módulo)

JavaScript no tenía campos de clase privados nativos hasta ES2022. Antes, los closures eran la forma idiomática de lograr encapsulamiento de datos:

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance; // verdaderamente privado — no accesible desde afuera

  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    withdraw(amount) {
      if (amount > balance) throw new Error("Insufficient funds");
      balance -= amount;
      return balance;
    },
    getBalance() {
      return balance;
    },
  };
}

const account = createBankAccount(100);
account.deposit(50);       // 150
account.withdraw(30);      // 120
console.log(account.balance); // undefined — ¡no accesible directamente!
```

### 3. Memoización

La **memoización** es una técnica de optimización que almacena en caché los resultados de llamadas a funciones costosas. Los closures son perfectos para almacenar el caché:

```js
function memoize(fn) {
  const cache = new Map(); // cerrado — vive tanto como la función memoizada

  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log("Cache hit!");
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

function slowFibonacci(n) {
  if (n <= 1) return n;
  return slowFibonacci(n - 1) + slowFibonacci(n - 2);
}

const fastFibonacci = memoize(slowFibonacci);
console.log(fastFibonacci(40)); // calculado
console.log(fastFibonacci(40)); // Cache hit! — instantáneo
```

### 4. Debounce

El **debounce** retrasa la ejecución de una función hasta después de un período de inactividad especificado. Es esencial para el rendimiento al manejar eventos de alta frecuencia como `input`, `resize` o `scroll`:

```js
function debounce(fn, delay) {
  let timeoutId; // cerrado — persiste entre llamadas

  return function (...args) {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}

const handleSearch = debounce((query) => {
  console.log("Searching for:", query);
}, 300);

// Solo se dispara una vez, 300ms después de que el usuario deje de escribir
document.querySelector("input")?.addEventListener("input", (e) => {
  handleSearch(e.target.value);
});
```

`timeoutId` es una variable privada que vive dentro del closure. Cada llamada a la función rebotada comparte el mismo `timeoutId`, permitiendo cancelar el timeout anterior.

> Lectura adicional: [MDN: setTimeout](https://developer.mozilla.org/en-US/docs/Web/API/setTimeout)

### 5. Iteradores

Los closures pueden crear iteradores con estado sin clases:

```js
function range(start, end, step = 1) {
  let current = start;

  return {
    next() {
      if (current <= end) {
        const value = current;
        current += step;
        return { value, done: false };
      }
      return { value: undefined, done: true };
    },
  };
}

const iter = range(1, 5);
console.log(iter.next()); // { value: 1, done: false }
console.log(iter.next()); // { value: 2, done: false }
console.log(iter.next()); // { value: 3, done: false }
```

> Lectura adicional: [MDN: Iterators and Generators](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Iterators_and_generators)

## La Trampa Clásica del Bucle

Uno de los bugs de closures más infames en JavaScript:

```js
// ROTO: usando var
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // imprime 3, 3, 3 — ¡no 0, 1, 2!
  }, 1000);
}
```

¿Por qué? Porque `var` tiene **alcance de función**, no de bloque. Los tres callbacks cierran sobre la **misma** variable `i`. Para cuando los timeouts se disparan, el bucle ha terminado e `i` es `3`.

**Solución 1: Usar `let`**

```js
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // 0, 1, 2 ✓
  }, 1000);
}
```

`let` tiene alcance de bloque. Cada iteración del bucle crea un **nuevo binding** de `i`, por lo que cada callback cierra sobre una variable diferente.

**Solución 2: IIFE (para bases de código más antiguas)**

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(function () {
      console.log(j); // 0, 1, 2 ✓
    }, 1000);
  })(i);
}
```

El IIFE crea un nuevo alcance en cada iteración, capturando el valor actual de `i` como el parámetro `j`.

> Lectura adicional: [MDN: let](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/let)

## El Patrón IIFE

Una **Expresión de Función Inmediatamente Invocada** (IIFE) es una función que se define y se llama al mismo tiempo:

```js
(function () {
  const privateData = "I am not global";
  console.log(privateData);
})();

// privateData no es accesible aquí
```

Los IIFE fueron la base del **patrón módulo** antes de que existieran los módulos ES. Permitían a las bibliotecas exponer solo una API pública manteniendo el estado interno privado:

```js
const Calculator = (function () {
  let history = []; // privado

  function add(a, b) {
    const result = a + b;
    history.push(`${a} + ${b} = ${result}`);
    return result;
  }

  function getHistory() {
    return [...history]; // retornar una copia para prevenir mutación
  }

  return { add, getHistory }; // API pública
})();

Calculator.add(2, 3); // 5
Calculator.getHistory(); // ["2 + 3 = 5"]
```

> Lectura adicional: [MDN: IIFE](https://developer.mozilla.org/en-US/docs/Glossary/IIFE)

### Cómo los Closures lo Impulsan

El mecanismo central:

```js
function typeWriter(element, text, speed = 50) {
  let index = 0; // cerrado por la función tick

  function tick() {
    if (index < text.length) {
      element.textContent += text[index];
      index++;
      setTimeout(tick, speed); // tick cierra sobre index y text
    }
  }

  tick();
}
```

`tick` es una función recursiva que cierra sobre `index` y `text`. Cada llamada a `typeWriter` crea un closure independiente, por lo que múltiples animaciones pueden ejecutarse simultáneamente sin interferir.


## Resumen

- Un **closure** es una función emparejada con su **entorno léxico** — las variables en alcance cuando se definió.
- Las funciones JavaScript llevan su `[[scope]]` consigo dondequiera que vayan a través de un slot interno.
- Las variables cerradas viven en el **heap**, no en la pila, por lo que sobreviven la ejecución de su función envolvente.
- El **modelo mental de la mochila**: las funciones internas llevan sus variables circundantes como una mochila invisible.
- Patrones clave habilitados por closures: funciones fábrica, estado privado, memoización, debounce, iteradores y currying.
- La **trampa clásica del bucle** ocurre porque `var` comparte un binding en todas las iteraciones del bucle; corrígela con `let` o un IIFE.
- Los **IIFE** fueron el patrón módulo original — crean un alcance privado y exponen solo una API pública.
