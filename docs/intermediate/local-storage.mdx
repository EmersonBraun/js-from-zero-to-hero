# Local Storage & Data Persistence

Modern browsers provide built-in storage APIs that let your JavaScript applications remember data between page reloads and browser sessions — without needing a server or database. In this module you'll master `localStorage`, `sessionStorage`, and the JSON serialization patterns required to store complex data.

## Theory

### The localStorage API

`localStorage` is a key-value store attached to the current origin (protocol + hostname + port). Data persists indefinitely until explicitly cleared.

```js
// Store a value
localStorage.setItem('username', 'Alice');

// Retrieve a value (returns null if key doesn't exist)
const name = localStorage.getItem('username'); // 'Alice'

// Remove a specific key
localStorage.removeItem('username');

// Clear ALL keys for this origin
localStorage.clear();

// Check how many keys are stored
console.log(localStorage.length);

// Iterate over all keys
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i);
  const value = localStorage.getItem(key);
  console.log(key, value);
}
```

> **Important:** `localStorage` only stores strings. To store objects or arrays, you must serialize them.

---

### JSON.stringify and JSON.parse

Since `localStorage` is string-only, `JSON.stringify` converts objects/arrays to JSON strings, and `JSON.parse` converts them back:

```js
// Storing an object
const user = { name: 'Alice', age: 30, hobbies: ['coding', 'reading'] };
localStorage.setItem('user', JSON.stringify(user));

// Retrieving and parsing
const stored = localStorage.getItem('user');
const parsed = JSON.parse(stored);
console.log(parsed.name); // 'Alice'

// Safe parsing (handles null and malformed JSON)
function safeGet(key, defaultValue = null) {
  try {
    const item = localStorage.getItem(key);
    return item !== null ? JSON.parse(item) : defaultValue;
  } catch (e) {
    return defaultValue;
  }
}
```

---

### CRUD Patterns

A standard pattern for managing a collection in `localStorage`:

```js
const STORAGE_KEY = 'my-todos';

// Create — add a new item
function createItem(text) {
  const items = readAll();
  const newItem = { id: Date.now(), text, done: false, createdAt: new Date().toISOString() };
  items.push(newItem);
  localStorage.setItem(STORAGE_KEY, JSON.stringify(items));
  return newItem;
}

// Read — get all items
function readAll() {
  const raw = localStorage.getItem(STORAGE_KEY);
  return raw ? JSON.parse(raw) : [];
}

// Update — toggle done status
function updateItem(id, changes) {
  const items = readAll();
  const updated = items.map(item => item.id === id ? { ...item, ...changes } : item);
  localStorage.setItem(STORAGE_KEY, JSON.stringify(updated));
}

// Delete — remove by id
function deleteItem(id) {
  const items = readAll().filter(item => item.id !== id);
  localStorage.setItem(STORAGE_KEY, JSON.stringify(items));
}
```

---

### Data Persistence Strategies

When designing localStorage-backed apps, consider:

- **Versioning:** Store a `_version` key alongside your data. If the stored version differs from the app version, migrate or reset the data.
- **Quota:** `localStorage` is typically limited to ~5MB per origin. Store only what you need.
- **Expiration:** `localStorage` has no built-in TTL. If you need expiry, store a timestamp and check it on read.

```js
function setWithExpiry(key, value, ttlMs) {
  const item = { value, expiry: Date.now() + ttlMs };
  localStorage.setItem(key, JSON.stringify(item));
}

function getWithExpiry(key) {
  const raw = localStorage.getItem(key);
  if (!raw) return null;
  const item = JSON.parse(raw);
  if (Date.now() > item.expiry) {
    localStorage.removeItem(key);
    return null;
  }
  return item.value;
}
```

---

### sessionStorage vs localStorage

| Feature | `localStorage` | `sessionStorage` |
|---|---|---|
| Persistence | Until explicitly cleared | Until tab/window closes |
| Scope | All tabs of the same origin | Single tab only |
| Capacity | ~5MB | ~5MB |
| API | Identical | Identical |

Use `sessionStorage` for temporary state like form drafts or wizard steps where you don't want data to carry over between sessions.

A full-featured todo application that remembers your tasks across page refreshes using `localStorage`.

#### How it works

On page load, todos are read from `localStorage` and rendered to the DOM. Every mutation (add, toggle, delete) updates both the DOM and `localStorage` immediately.

```js
const STORAGE_KEY = 'js-hero-todos';

function loadTodos() {
  return JSON.parse(localStorage.getItem(STORAGE_KEY) || '[]');
}

function saveTodos(todos) {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(todos));
}

function renderTodo(todo, listEl) {
  const li = document.createElement('li');
  li.dataset.id = todo.id;
  if (todo.done) li.classList.add('done');

  const span = document.createElement('span');
  span.textContent = todo.text;

  const toggleBtn = document.createElement('button');
  toggleBtn.className = 'toggle';
  toggleBtn.textContent = 'Done';

  const deleteBtn = document.createElement('button');
  deleteBtn.className = 'delete';
  deleteBtn.textContent = 'Remove';

  li.append(span, toggleBtn, deleteBtn);
  listEl.appendChild(li);
}

function renderTodos(todos, listEl) {
  listEl.replaceChildren(); // clear existing items safely
  todos.forEach(todo => renderTodo(todo, listEl));
}
```

Card data and matched state are kept in a `gameState` object. After every move, the state is serialized and saved. On page load, the stored state (if valid) is restored, allowing the player to continue a game in progress.

```js
function shuffle(array) {
  return [...array].sort(() => Math.random() - 0.5);
}

function saveGame(state) {
  localStorage.setItem('memory-game', JSON.stringify(state));
}

function loadGame() {
  try {
    return JSON.parse(localStorage.getItem('memory-game'));
  } catch {
    return null;
  }
}

let gameState = loadGame() || initNewGame();
```

#### How it works

Each day gets its own `localStorage` key based on the current date (e.g., `water-2024-03-15`). Old keys are automatically cleaned up on load.

```js
function getTodayKey() {
  return `water-${new Date().toISOString().split('T')[0]}`;
}

function getIntake() {
  return parseInt(localStorage.getItem(getTodayKey()) || '0', 10);
}

function addCup(ml) {
  const current = getIntake();
  localStorage.setItem(getTodayKey(), String(current + ml));
  updateUI();
}
```

## Summary

In this module you learned:

- The `localStorage` and `sessionStorage` APIs: `setItem`, `getItem`, `removeItem`, `clear`.
- Why JSON serialization is required and how to use `JSON.stringify` and `JSON.parse` safely.
- A complete **CRUD pattern** for managing collections in client-side storage.
- Strategies for handling storage quota, data expiry with TTL, and schema migrations.
- The key differences between `localStorage` (persistent, cross-tab) and `sessionStorage` (tab-scoped, ephemeral).

Data persistence is the gateway to real applications. The Todo List, Memory Game, and Drink Water Tracker demonstrate how the same simple API can power a wide variety of practical projects.
