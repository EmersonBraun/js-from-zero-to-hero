# `this`, Protótipos & Classes

## A Palavra-chave `this`

`this` é uma das partes mais confusas do JavaScript — mas ela segue regras claras e determinísticas. O valor de `this` é **determinado não por onde uma função é definida, mas por como ela é chamada**. Isso é o oposto das closures (que são determinadas por onde uma função é definida).

> "Na maioria dos casos, o valor de `this` é determinado por como uma função é chamada (vinculação em tempo de execução). Não pode ser definido por atribuição durante a execução, e pode ser diferente cada vez que a função é chamada."
>
> — [MDN: this](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/this)

Existem **quatro regras de vinculação** para `this`, aplicadas em ordem de precedência.

---

## As Quatro Regras de Vinculação

### Regra 1: Vinculação Padrão

Quando uma função é chamada como uma **função simples e independente** (não como método), `this` assume por padrão:

- O **objeto global** (`window` em navegadores, `global` no Node.js) em modo não-estrito
- `undefined` no **modo estrito**

```js
function showThis() {
  console.log(this);
}

showThis(); // window (navegador) ou global (Node) — ou undefined em modo estrito
```

```js
"use strict";
function showThis() {
  console.log(this); // undefined
}
showThis();
```

> Leitura adicional: [MDN: strict mode](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Strict_mode)

### Regra 2: Vinculação Implícita

Quando uma função é chamada como **método de um objeto**, `this` refere-se ao objeto à **esquerda do ponto** no momento da chamada:

```js
const user = {
  name: "Alice",
  greet() {
    console.log(`Hello, I'm ${this.name}`);
  },
};

user.greet(); // "Hello, I'm Alice" — this = user
```

**A vinculação implícita pode ser perdida** quando métodos são extraídos e chamados de forma independente:

```js
const { greet } = user;
greet(); // "Hello, I'm undefined" — this agora é global/undefined, não user!
```

Esse é um bug muito comum. A função `greet` não tem mais um receptor implícito — ela reverte para a vinculação padrão.

### Regra 3: Vinculação Explícita — `call`, `apply` e `bind`

Você pode forçar a definição de `this` usando três métodos embutidos:

**`Function.prototype.call(thisArg, arg1, arg2, ...)`** — chama a função imediatamente com um `this` específico:

```js
function introduce(greeting) {
  console.log(`${greeting}, I'm ${this.name}`);
}

const person = { name: "Bob" };
introduce.call(person, "Hey"); // "Hey, I'm Bob"
```

**`Function.prototype.apply(thisArg, [argsArray])`** — igual a `call`, mas os argumentos são passados como array:

```js
introduce.apply(person, ["Howdy"]); // "Howdy, I'm Bob"
```

**`Function.prototype.bind(thisArg, ...partialArgs)`** — retorna uma **nova função** permanentemente vinculada a `this`. Ao contrário de `call`/`apply`, não chama a função imediatamente:

```js
const bobIntro = introduce.bind(person);
bobIntro("Hi"); // "Hi, I'm Bob"

// bind também suporta aplicação parcial:
const greetBob = introduce.bind(person, "Hello");
greetBob(); // "Hello, I'm Bob"
```

> Leitura adicional: [MDN: Function.prototype.bind](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/bind)

### Regra 4: Vinculação com `new`

Quando uma função é chamada com a palavra-chave `new`, quatro coisas acontecem automaticamente:

1. Um novo objeto vazio `{}` é criado
2. O `[[Prototype]]` do novo objeto é definido como `Constructor.prototype`
3. A função é chamada com `this` apontando para o novo objeto
4. O novo objeto é retornado (a menos que o construtor retorne explicitamente um objeto diferente)

```js
function Person(name, age) {
  this.name = name; // this = o novo objeto
  this.age = age;
}

const alice = new Person("Alice", 30);
console.log(alice.name); // "Alice"
console.log(alice instanceof Person); // true
```

> Leitura adicional: [MDN: new operator](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/new)

### Precedência de Vinculação

Quando múltiplas regras poderiam se aplicar, `new` > explícita > implícita > padrão.

## Arrow Functions e `this` Léxico

Arrow functions `() => {}` **não** têm seu próprio `this`. Em vez disso, elas **herdam `this` do escopo léxico envolvente** no momento em que são definidas. Isso é chamado de **`this` léxico**.

```js
const timer = {
  seconds: 0,
  start() {
    // 'this' aqui é o objeto timer
    setInterval(() => {
      this.seconds++; // arrow function: this = timer (léxico)
      console.log(this.seconds);
    }, 1000);
  },
};

timer.start(); // 1, 2, 3, ...
```

Se usássemos uma função regular em `setInterval`, `this` seria `window`/`undefined` (vinculação padrão), não `timer`.

> Leitura adicional: [MDN: Arrow function expressions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Arrow_functions)

### O Padrão `that = this` (Pré-Arrow)

Antes das arrow functions, os desenvolvedores usavam uma variável (frequentemente chamada `self` ou `that`) para capturar `this`:

```js
const timer = {
  seconds: 0,
  start() {
    const self = this; // capturar this
    setInterval(function () {
      self.seconds++; // usar referência capturada
      console.log(self.seconds);
    }, 1000);
  },
};
```

As arrow functions tornaram esse padrão obsoleto.

## A Cadeia de Protótipos

Todo objeto JavaScript tem um link interno para outro objeto chamado seu **protótipo** (armazenado como `[[Prototype]]`, acessível via `Object.getPrototypeOf()` ou o legado `__proto__`). Quando você acessa uma propriedade em um objeto e ela não é encontrada, o JavaScript percorre automaticamente a cadeia de protótipos:

```
myObj → Object.prototype → null
```

```js
const animal = {
  type: "Animal",
  describe() {
    return `I am a ${this.type}`;
  },
};

const dog = Object.create(animal); // [[Prototype]] de dog = animal
dog.type = "Dog";

console.log(dog.describe()); // "I am a Dog"
// describe não está em dog — é encontrado no protótipo de dog (animal)
```

> Leitura adicional: [MDN: Inheritance and the prototype chain](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Inheritance_and_the_prototype_chain)

### `Object.create`

`Object.create(proto)` cria um novo objeto com `proto` como seu `[[Prototype]]`. Esta é a forma mais pura de configurar delegação de protótipo:

```js
const vehicleProto = {
  describe() {
    return `${this.make} ${this.model} (${this.year})`;
  },
};

const car = Object.create(vehicleProto);
car.make = "Toyota";
car.model = "Camry";
car.year = 2023;

console.log(car.describe()); // "Toyota Camry (2023)"
console.log(Object.getPrototypeOf(car) === vehicleProto); // true
```

> Leitura adicional: [MDN: Object.create](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/create)

### Funções Construtoras e `prototype`

Funções construtoras antecedem a sintaxe `class`. Toda função tem uma propriedade `prototype` — um objeto que se torna o `[[Prototype]]` das instâncias criadas com `new`:

```js
function Animal(name) {
  this.name = name;
}

// Métodos no protótipo são COMPARTILHADOS por todas as instâncias
Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

const cat = new Animal("Cat");
const dog = new Animal("Dog");

console.log(cat.speak()); // "Cat makes a sound."
console.log(dog.speak()); // "Dog makes a sound."

// Ambas as instâncias compartilham a mesma função speak:
console.log(cat.speak === dog.speak); // true — eficiente em memória!
```

Colocar métodos no protótipo (em vez de dentro do construtor) é eficiente em memória: em vez de cada instância ter sua própria cópia, todas compartilham uma via a cadeia.

## Classes ES6: Açúcar Sintático

A palavra-chave `class`, introduzida no ES6, fornece uma sintaxe mais limpa para o mesmo mecanismo baseado em protótipo. Classes **não** são um novo modelo de objeto — elas são açúcar sintático sobre funções construtoras e protótipos.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

const cat = new Animal("Cat");
console.log(cat.speak()); // "Cat makes a sound."

// Por baixo dos panos, speak ainda está no protótipo:
console.log(typeof Animal.prototype.speak); // "function"
```

### Métodos Estáticos

Métodos estáticos pertencem à classe em si, não às instâncias. Eles são chamados diretamente na classe:

```js
class MathUtils {
  static add(a, b) {
    return a + b;
  }

  static PI = 3.14159;
}

console.log(MathUtils.add(2, 3)); // 5
console.log(MathUtils.PI);        // 3.14159

const m = new MathUtils();
// m.add(2, 3); // TypeError: m.add is not a function
```

> Leitura adicional: [MDN: static](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/static)

### Campos Públicos e Privados (`#`)

O ES2022 introduziu **campos de classe**. Campos privados usam o prefixo `#` e são verdadeiramente inacessíveis de fora da classe — aplicado no nível da linguagem, não apenas por convenção:

```js
class BankAccount {
  #balance; // declaração de campo privado
  owner;    // campo público

  constructor(owner, initialBalance) {
    this.owner = owner;
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}

const account = new BankAccount("Alice", 1000);
account.deposit(500);
console.log(account.balance); // 1500
// console.log(account.#balance); // SyntaxError: Private field '#balance'
```

> Leitura adicional: [MDN: Private class features](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/Private_class_fields)

### Herança com `extends` e `super`

`extends` configura a cadeia de protótipos entre classes. `super` chama o construtor ou métodos da classe pai:

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // DEVE chamar super() antes de usar this
    this.breed = breed;
  }

  speak() {
    return `${this.name} barks!`;
  }

  describe() {
    return `${super.speak()} I am a ${this.breed}.`;
  }
}

const rex = new Dog("Rex", "Labrador");
console.log(rex.speak());    // "Rex barks!"
console.log(rex.describe()); // "Rex makes a sound. I am a Labrador."
console.log(rex instanceof Animal); // true — cadeia de protótipos
console.log(rex instanceof Dog);    // true
```

> Leitura adicional: [MDN: extends](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Classes/extends)

### Visão Geral da Arquitetura

```js
class Player {
  #name;
  #symbol;
  #score;

  constructor(name, symbol) {
    this.#name = name;
    this.#symbol = symbol;
    this.#score = 0;
  }

  get name() { return this.#name; }
  get symbol() { return this.#symbol; }
  get score() { return this.#score; }

  addWin() { this.#score++; }
}

class Board {
  #cells;

  constructor() {
    this.#cells = Array(9).fill(null);
  }

  mark(index, symbol) {
    if (this.#cells[index] !== null) throw new Error("Cell taken");
    this.#cells[index] = symbol;
  }

  checkWinner() {
    const lines = [[0,1,2],[3,4,5],[6,7,8],[0,3,6],[1,4,7],[2,5,8],[0,4,8],[2,4,6]];
    return lines.some(([a,b,c]) =>
      this.#cells[a] && this.#cells[a] === this.#cells[b] && this.#cells[a] === this.#cells[c]
    );
  }
}
```

Observe como `this` dentro de métodos de classe sempre refere-se à instância, porque handlers de eventos devem sempre usar arrow functions ou `bind` para preservar a referência da instância do jogo.

## Resumo

- `this` é determinado **no momento da chamada** por quatro regras: padrão, implícita, explícita (`call`/`apply`/`bind`) e `new`.
- Arrow functions **não têm seu próprio `this`** — elas o herdam lexicamente do escopo envolvente.
- O padrão `that = this` era a solução pré-arrow.
- Todo objeto tem um `[[Prototype]]` — um link para outro objeto. Buscas de propriedades percorrem essa **cadeia de protótipos**.
- `Object.create(proto)` cria um objeto com um protótipo específico.
- Funções construtoras + propriedade `prototype` é a abordagem clássica para métodos compartilhados.
- `class` é açúcar sintático: sintaxe mais limpa, mesma mecânica baseada em protótipo.
- Membros `static` pertencem à classe, não às instâncias.
- Campos privados `#campo` são aplicados pela linguagem — não apenas uma convenção de nomenclatura.
- `extends` + `super` habilitam herança limpa e legível.
